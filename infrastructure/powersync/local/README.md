# UAF Household Vault — ₹0 incremental hosted-cost local sync pilot

**Experimental, local-only.** This supplements (does not replace) existing
Gate 2/3 tests. It uses the original Household Vault app, **checked-in
canonical** `../sync-config.yaml`, disposable Supabase/Postgres/Auth/
Edge Functions, self-hosted PowerSync Open Edition and MongoDB. It
does not use hosted Supabase, PowerSync Cloud, Cloudflare, or private
business data, and **does not change PR #5/main deployment gates**.

## Prerequisites

- Windows: Docker Desktop with WSL 2 and an Ubuntu WSL terminal. Linux/macOS
  with a working Docker/Compose engine are also possible.
- Docker Compose v2 with the `--wait` flag; allocate enough local memory
  for Supabase + MongoDB + PowerSync + Chromium. Supabase's guide recommends
  at least **7 GB RAM available to Docker** for the standard local stack.
- Node.js 24, pinned pnpm 10.15.1; run `pnpm install --frozen-lockfile`
  from repository root.
- A private/trusted network and no public port forwarding, tunnel, reverse
  proxy, internet-facing VM or shared Wi-Fi access. The Supabase CLI
  development stack has **no production hardening**. PowerSync alone binds
  `127.0.0.1:54399`; verify how your Docker engine exposes the *Supabase*
  CLI ports before running on an untrusted network.
- `gate2-security-hardening` is the base branch for this **stacked draft**.
  This local experiment is not a proposed production or staging release.

## Run on a trusted local Linux/WSL Docker environment

Execute from the repository root:

```bash
corepack enable
corepack prepare pnpm@10.15.1 --activate
pnpm install --frozen-lockfile
docker info
node scripts/validate-local-powersync-gate.mjs --self-test

cd infrastructure
../node_modules/.bin/supabase gen signing-key --algorithm ES256 --append
../node_modules/.bin/supabase start --exclude studio,imgproxy,mailpit,realtime,storage-api,logflare,vector,supavisor
../node_modules/.bin/supabase db reset --local --no-seed
cd ..

docker network inspect supabase_network_uaf-household-vault-local
docker compose -f infrastructure/powersync/local/compose.yaml up -d --wait
curl -fsS http://127.0.0.1:54399/probes/liveness
```

Use local-only Supabase status for the local API URL and **publishable**
client key; never paste the local secret/service-role key into the
frontend. The reference app's local-sync browser tests use two disposable
accounts generated by `scripts/gate3-seed-local-auth.mjs` in a **GitHub
Actions runner**, which provides `GITHUB_ENV`. That CI seeder is not a
general-purpose manual-user provisioning command.

For a complete reproducible build + nine connected browser journeys,
use the [draft PR's local full-sync CI workflow](../../../.github/workflows/gate3-local-powersync-e2e.yml).
It performs the setup and synthetic seeding without adding hosted
secrets. The full browser report is validated for **zero missing, skipped,
failed, flaky or retried scenarios**. It is a disposable *localhost* test,
**not** proof that a Cloudflare-hosted PWA is private or production-ready.

## Stop and delete ONLY the disposable local services

```bash
docker compose -f infrastructure/powersync/local/compose.yaml down --volumes --remove-orphans
cd infrastructure
../node_modules/.bin/supabase stop --no-backup
```

The Compose `--volumes` and Supabase `--no-backup` options **destroy
local synthetic data**, not any hosted project. Do not use either command
on a different Compose project or Supabase directory. The generated
`infrastructure/supabase/signing_key.json` is gitignored and must never
be committed. If in doubt about container selection, inspect with
`docker compose ... ps` and `supabase status` before cleanup.

## Boundaries and known failure conditions

- **No Supabase link/login or remote flags.** Never use `--linked`,
  `supabase db push`, hosted connection URIs, or a real business account.
- Uses local Postgres's default disposable `postgres` password and
  private Supabase Docker network. It is *unsafe* on an internet-accessible
  machine without isolation.
- Auth JWTs use ephemeral **ES256** local signing keys. PowerSync's JWKS
  is fetched from local Supabase Kong. A missing/legacy signing key should
  fail rather than disabling token verification.
- If the expected Supabase Docker network does not exist, do not point
  PowerSync at a hosted database or another project's network. Inspect
  the local CLI version/network ID and adjust only after review.
- The self-hosted PowerSync image is pinned to service **v1.27.0**
  (released 6 Oct 2026); `mongo:7.0` is a pinned major line for this
  experiment, not a production image-digest attestation.
- Don't generalize this test's successful execution to real-device PWA,
  production SSO, Worker-level Access, mobile OS storage or 24/7 hosting.
  Gate 3 remains NO-GO until separately authorized private hosted tests.
